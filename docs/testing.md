# Testing

> Status: Stable. See [Maturity](maturity.md).

The suite combines concrete examples, randomized properties, and committed differential fixtures.

## Test layers

- Concrete tests cover documented behavior, boundaries, and error paths.
- Randomized tests use a deterministic seed and the `MITHQAL_PROPERTY_CASES` override.
- Differential fixtures record expected results generated by SymPy and committed to the repository.
- Numeric oracle fixtures record values generated by mpmath for elementary and special functions.
- Benchmark budgets run in the scheduled benchmark workflow.
- Catalog audit tests evaluate every advertised example, require documented changes for exact and approximate examples, and check kernel, catalog, and test coverage.
- Parser and pattern fuzz smoke tests exercise random source and pattern strings.
- Feature suites cover text, associations, files, contexts, packages, attributes, up values, messages, and advanced patterns.

## Differential fixtures

Fixtures live under `tests/fixtures/differential`. Each file uses tab separated fields and ignores comment and blank lines.

```text
factor<TAB>x^2-1<TAB>(x-1)*(x+1)
diff<TAB>x<TAB>sin(x)<TAB>cos(x)
integrate<TAB>x<TAB>x^2<TAB>(1/3)*x^3
det<TAB>[[1,2],[3,4]]<TAB>-2
probe<TAB>x=1/2<TAB>differentiate(sin(x),x)<TAB>0.877582...
```

The Rust test suite verifies these semantically. Factor results require the exact number of nonconstant factors and an exact expanded product. Rational results are combined and cancelled. Integrals are checked by differentiation. Matrix inverses are compared exactly.

Numeric probe records evaluate the operation result at rational assignments and compare against high precision SymPy values. This catches errors that the symbolic simplifier might share with the operation under test.

## Numeric oracle fixtures

`tests/fixtures/differential/numeric.tsv` records real and complex values for the numeric unary functions and the error and gamma functions. Each record names the function, gives the argument, and stores the real and imaginary parts rounded to 50 significant digits. The Rust test evaluates `approx` at 50 digits, compares both parts against the fixture, and checks that the reported precision stays above 40 digits.

```text
gamma<TAB>real<TAB>-0.5<TAB>-3.544907...<TAB>0
acosh<TAB>complex<TAB>complex(-2,-1)<TAB>1.469351...<TAB>-2.634236...
```

Regenerate the file with:

```text
python3 -m venv /tmp/mpmath-venv
/tmp/mpmath-venv/bin/pip install mpmath
/tmp/mpmath-venv/bin/python tools/generate_mpmath_fixtures.py
```

Complex `lgamma` records use the principal logarithm of the gamma value, matching the engine definition. Complex `acosh` records use the principal branch with a nonnegative real part.

Failure records cover three outcomes:

```text
unevaluated<TAB>inverse([[1,2],[2,4]])<TAB>inverse
diagnostic<TAB>differentiate(x)<TAB>TGN-EVAL-0013
unchanged<TAB>factor(x^2+y^2+1)<TAB>x^2+y^2+1
```

`unevaluated` checks the returned call head. `diagnostic` checks the stable error code. `unchanged` checks that an operation leaves the expression mathematically unchanged.

Exact value records cover number theory and statistics:

```text
equal<TAB>totient(360)<TAB>96
equal<TAB>factorInteger(360)<TAB>[[2,3],[3,2],[5,1]]
equal<TAB>variance([1,2,3,4])<TAB>5/4
equal<TAB>frequency([1,1,2])<TAB>[[1,2],[2,1]]
```

## Regenerating fixtures

The generators are developer tooling and are not part of the crate build. They require SymPy and mpmath outside the Rust dependency graph.

```text
python3 -m pip install sympy==1.14.0
python3 tools/generate_differential_fixtures.py
```

Review the generated diff before committing it. A scheduled workflow reruns the generator with the current SymPy release and reports fixture drift without blocking pull requests.

## Mithqalite acceptance status

Mithqalite has separate routine and stress suites. The routine float gate runs
4,655 tests in about 3.5 minutes with a warm build, plus about 3 seconds for
doctests. It ignores 58 huge-precision and huge-pi stress tests. The routine nz
gate runs 6,345 tests in about 2.5 minutes and ignores one large-multiplication
stress test.

The complete float suite is not a routine gate. A four-core run took 5 hours 49
minutes because the extreme-precision tests compute constants such as pi to
about 2^30 bits. Those tests remain available through the Mithqalite stress
scripts.

Float coverage is 92.13% of lines and 93.60% of branches after excluding test
utilities. It reaches 95.04% of lines and 96.96% of branches after also
excluding three modules that contain only delegation wrappers for
`mul_add_mul`, `mul_sub_mul`, and `rem`. Their shared implementations are
covered through the non-wrapper tests.

nz coverage has not been measured yet. The initial full measurement was
interrupted before producing results, so nz confidence is not quantitatively
guaranteed. A gentler measurement focused on the core natural and integer
modules used by Mithqal is being prepared. Until it is complete, treat the nz
gate as broad regression coverage rather than a measured 95% confidence claim.

## Long property runs

The default case count is 32. CI uses 128. Use a larger value locally for a soak run.

```text
MITHQAL_PROPERTY_CASES=1024 cargo test --test randomized --test randomized_numeric
```
